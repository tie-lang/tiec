# p.9.2.1 崩溃诊断 Crash Diagnostics

**状态**：已实现（p.9 工具链 / 编译器侧仓库 tiec）。
**交付**：解释器运行期 panic 的 backtrace + 符号化 + 崩溃日志文件。

## 目标与定界（务实裁决）
- **捕获对象**：用户程序在解释器（compiler/interp）执行期的 **panic**（`g_err` 置位，
  如除零、table_at 越界、未定义函数调用等）。这是高频、可符号化的崩溃形态。
- **编译器自身崩溃**（tiec.exe 本体段错误 / 断言）不再本子项：需原生地址符号化 +
  重复复现火焰图，属「重症诊断」另一路径，本文档记为接口预留，
  与崩溃日志同一目录扩展（`*.dmp` 原生崩溃留待 p.9.2.4 剖析扩展）。
- **符号化来源**：解释器调用栈。`interp_dbug` 在 `call_fn` 进入/退出维护帧栈
  （帧 = 函数名 + 函数体首行），`g_err` 首次置位时对最内层栈做快照。解释器语境下
  “符号化” = 帧指针 → 函数名 + 源码行号映射（非 native 地址反查 `.ll/.sym`）。

## 交付物
| 文件 | 说明 |
|------|------|
| `compiler/interp/interp_dbug.tie` | 共享仪器：调用栈 + 里程碑事件流 + 崩溃快照（默认关） |
| `compiler/interp/interp_call.tie` | `call_fn` 进/出调用 `dbg_enter/dbg_leave` |
| `compiler/interp/interp.tie` | `exec_stmt` 调用 `dbg_stmt_hook`（供 DAP/剖析复用）；import 仪器 |
| `compiler/dbug/crashdiag.tie` | 崩溃诊断工具（tiec 编译为 crashdiag.exe） |
| `scripts/verify-crashdiag.tsh.tie` | 验收脚本（tsh 角色，含自举不动点复核） |
| `compiler/dbug/_crash_probe.tie` / `_ok_probe.tie` | 崩/正两探针 |

## 用法
被测程序须为**模块式**（只定义函数）、入口为无参 `func main()`：
```
tiec compiler\dbug\crashdiag.tie -o compiler\dbug\crashdiag.exe   # 构建工具
compiler\dbug\crashdiag.exe [-o <日志>] <program.tie>
```
- 退出码：`0` 正常运行结束；`1` 运行期 panic（已写崩溃日志）；`2` 参数/加载错误。
- 默认日志：`<program>.crash.log`。报告含时间戳、程序、错误消息、符号化调用栈。

## 崩溃日志示例
```
=== tie 崩溃诊断 (p.9.2.1) ===
时间戳: 1789260536
程序: compiler\dbug\_crash_probe.tie
错误: 除零错误
调用栈 (backtrace, 自外向内):
  #0 main (行:20)
  #1 a (行:15)
  #2 b (行:10)
  #3 boom (行:4)
```

## 验收
`<tsh> -f scripts/verify-crashdiag.tsh.tie`（崩溃 backtrace 含 main->a->b->boom、正常探针退出 0 且无日志、
tiec 自举不动点二次 SHA256 一致）。
