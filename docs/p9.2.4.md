# p.9.2.4 剖析器（Profiler：CPU 采样 + 内存剖析接口 + 火焰图）

**状态**：已实现（p.9 工具链 / 编译器侧仓库 tiec）。
**交付**：运行期插桩函数级调用采样 + **折叠栈**（folded stacks）+ **文本火焰图**；
内存剖析为**接口预留**。

## 定界（务实裁决）
- **采样方式**：运行期插桩。复用 interp_dbug 的里程碑事件流——`interp.call_fn` 在
  C/R 打 time_now() 秒级时间戳（默认关），profiler 工具跑一遍被测程序后据此统计
  「调用次数 + 含子(inclusive)/自耗(exclusive) 秒」。
- **主权重**：**调用次数**（CPU 热路径 = 高调用频率）；由于 time_now() 为秒级，
  快速函数的含子/自耗秒常为 0 —— 毫秒级耗时需在**独立工具**内自声明 CRT `clock()`
  扩展（interp_dbug 随 tiec.exe 并入，**不得**声明与 driver 重复的 extern clock）。
- **折叠栈**：以 ";" 连接调用路径，权重 = count（主）/含子秒（次）。
- **火焰图**：文本（ASCII 条形，按权重降序，限前 20 条）。SVG 火焰图生成器可随后
  复用折叠栈输出做成 HTML/SVG（接口一致）。
- **内存剖析**：**接口预留**。建议在 ivalue.new_*（new_int/new_table/new_str 等）插桩
  计数，或对 value 池做周期采样；本文档记录挂载点，不在本子项实现（成本高 + 运行至
  完成模型下采样粒度有限）。

## 交付物

| `compiler/dbug/profiler.tie` | 剖析器（tiec→profiler.exe） |

| `compiler/interp/interp_dbug.tie` | 事件采样（已在 p.9.2.1 加入，被复用） |

## 用法
```
tiec compiler\dbug\profiler.tie -o compiler\dbug\profiler.exe
compiler\dbug\profiler.exe [-o <out>] <program.tie>
```
- 被测程序为模块式（只定义函数）、入口无参 `func main()`。
- `-o` 写报告到文件；缺省打印到 stdout。

## 验收
`pwsh ./scripts/verify-profiler.ps1`：profiler 运行成功、每函数含 main/fib/hot、
fib 调用数(23) > hot(1)、折叠栈含 main;hot 与 main;fib;fib、含火焰图节。
