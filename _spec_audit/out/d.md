## 本路结论

1. **最严重未实现（一）——actor 字段初值被静默丢弃**（10.8）：`actor C { var n: i64 = 5 }` 编译无警告无报错，运行读到 0。规范 §10.8 要求初值生效；根因在 `irgen_rt_p2.tie:180-188` 用 `tig_default_val(fty)` 覆盖字段槽，解析期保留的初值节点从未被消费。规范自己的示例初值恰全为零值，因此缺陷在示例内不可观测——这是「编译通过 ≠ 语义正确」的典型样本，建议优先修。

2. **最严重未实现（二）——并发两张图/两个关键字整体缺席**：任务图（10.4/10.9）`graph()` 与图字面量 `{A}-{B}->{C->~A}` 均不支持（`E00489`/`E00481`，`~` 连 token 都不是）；重入 `reentrant`（10.7）非关键字（`E00484`）。第 10 章十项可判定条目里，状态单元与消息调用已可用，但「带依赖的并行调度」与「打破等待环路」这两大机制完全没有实现痕迹。

3. **编译器内部错误（ICE）——内联汇编占位符导致 tiec.exe 段错误**（11.7）：`asm!("mov {0}, 1", out(reg) n)` 触发 tiec.exe 段错误（exit 139，连跑 2 次稳定复现）；`asm!` 模板里的 `{d}` 同样崩溃。实现里确有 `{N}`→`$N` 转换（llvmgen_str.tie:161），但普通字符串的 `{...}` 先被字符串插值吃掉、raw 字符串又因 `r` 前缀未剥离而 LLVM 报错，**两条路径都不可达**——即带操作数的内联汇编实质不可用。建议单独立项修：至少要把「模板含 `{N}`」从崩溃降级为明确诊断。

4. **规范与实现正面冲突（记号层，建议改规范或改实现）**：
   * `\` 解引用记号（§11.6 `\p = as_u8(1)`）：实现里 `\` 是**整除运算符**（`7 \ 2` = 3，pexpr_p1.tie:396），`\p` 报 `E00000`。同一符号两种语义，必须二选一。
   * 宏的准引用/插值记号：实现认**反引号 + `$`**（pexpr_p3.tie:300/361），规范 §12.1–§12.4 写 `quote { }` + `@`、§12.6 又写反引号 + `$`。**规范自身不一致**，按实现统一即可：全局改为 `` `{ } ``/`` `( ) `` + `$x`/`$(expr)`。
   * `#cfg` 键名：实现只认英文 `os/target/debug/release`，规范示例用中文键 `平台`（恒为假、静默走 else）。建议规范改用英文键并列出允许键集。

5. **规范领先/落后于实现的两处（对账焦点）**：
   * §11.6 凭据系统**规范领先**：规范的「中文五域 + move-only + revoke + `delegate()` 无参」在实现里分别是中文四域（share/trm/mem/ext）、无 move-only、无 revoke、`delegate` 须带域名参数；但 `get/use/with/绑定对象/文件级授权` 已能用——ROAD.md:372 标 `[ ]` 未落地属**记录低估**，建议改 `[~]`。
   * §11.8 重分类**规范领先**：atomic/slice/ptr 三条仍全部在 unsafe 门内（`E00376`/`E00358`），与 ROAD.md:371 `[ ]` 一致；仅 `repr(C) struct` 可用（属性形态 `#[repr(C)]` 未实现）。

6. **编译期求值的静默错误**（12.4）：全局 `const` 里 `+ - * / %` 折叠正确，但 `<< >> & | ^` **一律静默得 0**（`consteval.tie` 二元分支未覆盖这些 op，失败后仍以 0 采用）。这是纯静默错误、无任何诊断，且规范 §12.4 的示例 `const TABLE_SIZE = 1 << 10` 正好命中（另加无类型标注报 `E00284`）。

7. **所有权章节的实情**（13）：按值、`move` 形参、`immut`/`ref` 均已落地；缺的是 `var b = move a` 表达式（`E00000`）、`xs.clone()` 方法（表/串/结构均无）、以及「已移动后使用」检查**默认关闭**（需 `TIE_MOVE_CHECK=1` 才报 `E00372`，默认下移出后使用既无诊断也无运行期后果）。ROAD.md:359 对此有自述，属实。
