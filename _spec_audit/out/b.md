## 本路结论

1. **ch04 实现度高（40/45 已实现）**，4.8–4.14 的「现代控制流」全部落地：条件解构、guard、defer、try 错误聚合块、`#[tag]`+`unsafe goto`、分支即表达式、四种位置解构，实测均可编译运行且语义正确。
2. **最严重的 ch04 未实现项**：`count %%= 5`（规范 §4.2 的复合赋值写法）——符号表根本没有 `%%=`，被切成 `%%` + `=` 直接报 E00000。规范把 `%%=` 与 `+=`/`*=` 并列展示，是**规范虚构的运算符**。
3. **ch05 是最需要留意的章**：5.1–5.12 主体可用，但**规范示例的一批「写法」逐字照抄都编译不过**——`return a/b, a%b`（须加括号）、`var q, r = `（须加括号）、`extern func`（须 `unsafe extern fn`）、`func log(x) = …`（须 `-> void`）、`func connect(…, port: i64 = 8080)`（`port` 是保留字）、闭包实参位省形参类型。这些是「规范示例常有偏差」的连续实证，不是实现缺失。
4. **规范与实现冲突（≤5）**：
   * §5.10「捕获一律值语义，表内修改不影响外围同名表」——**实测表按引用捕获**（s5_10d/s5_10d2），闭包内外共享同一表。
   * §4.2「语言不做隐式的窄化转换」——**实测变量→窄类型静默截断**（i64 300 → i8 44），仅字面量越界报 E00377。
   * §5.2「可写借用要求实参是可寻址的对象」——实现更严，`[1,2]` 初始化的定长表被拒（E00590），仅 `table_new_*` 动态表可作 ref 实参。
   * §5.3「默认值必须是常量表达式」——实现更严，仅**字面量**（const 引用被拒，E00359）。
   * §4.13 分支即表达式示例缺 `,` 分隔符，逐字照抄报 E00001。
