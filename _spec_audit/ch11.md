### 已修复的实现缺陷（3 处，本轮）

审计过程中发现 `asm!` 的**操作数**通路有 3 处缺陷，已全部 RCA 并修复
（tiec 提交见 `git log`；回归探针 `tests/language/asm_multi_probe.tie`）。

**① 含 `in`/`inout` 操作数 ⇒ 编译器内部错误「ir.add_operand 操作数段交错」**

```
编译器内部错误: ir.add_operand 操作数段交错 (fn=f inst=5007 op=65 off=9287 cnt=4
len_ops=9292 …)——调用方不得在 add_operand 序列中间向全局操作数段 push
（常量生成请先存变量）
```

* 复现最小化：`asm!("nop", in(reg) n)` —— **单个** in 操作数即崩；纯 `out` 一直正常。
* 根因：`tig_expr_seg2.tie` 的 asm 分支在 `ir.new_inst(65)` + 首个 `add_operand(模板)`
  **之后**才逐个对 in/inout 调 `tig_expr(e)`；而求值会发射新指令（load/const），其操作数
  被 push 进**全局操作数段**，恰好插在 inline_asm 已 push 的操作数**中间** —— 违反
  `add_operand` 的「不得交错」契约（错误消息自带指引）。
* 修法：改**两遍法** —— 先在发射 inline_asm 之前把所有 in/inout 入参求值到临时表，
  再一次性按序 `add_operand`。
* 现有档案 `atomic_asm.tie` 只用单 `out`，故长期未暴露。

**② 纯 `inout` ⇒ 生成 `call void asm …, "+r"(…)`（约束有输出却用 void 接收）**

* 根因：`out_slot`/`out_ty`（决定 call 返回类型）只在 `dir == 1`（out）时取，
  **inout(2) 也被漏掉** —— 于是 `ret_ty` 落 `void`，而约束串含输出 ⇒ LLVM 类型不匹配。
* 修法：判据扩为 `dir == 1 || dir == 2`。

**③ `inout` 的约束写成 GCC 风格 `+r`，LLVM 不认其输出**

* 现象：修 ② 后 `opt` 报 `inline asm without outputs must return void`，
  IR 为 `%5 = call i64 asm "add $0, 1", "+r"(i64 %4)`。
* 根因：LLVM IR 的 read-write 操作数**不是** GCC 的 `+r`，而是 **tied operand**：
  一个 `=r` 输出 + 一个「纯数字」输入约束（数字 = 绑定的输出序号），且 LLVM 要求
  输出约束构成约束串的**前部**。原实现按「操作数出现顺序」逐个拼，inout 夹在中间
  也会打乱输出/输入两段。
* 修法：`llvmgen_inst_gen_p1.tie` 改为**分段拼**（先输出段 `=r`…，再输入段），
  inout 生成 `=r` + 自身输出序号；IR 变为 `call i64 asm "add $0, 1", "=r,0"`。

> 附带结论（非缺陷）：`inout` 曾一度实测「编译通过但运行段错误（139）」，追查后确认是
> **样例模板写法错误**——tie 的 asm 是 **AT&T 方言**，立即数须写 `$$1`，写 `add $0, 1`
> 会被当内存操作数 `(1)` 而访问地址 1。改用 `inc $0` / `addq $$1, $0` 即正确（= 8）。
> 记在此处以免后续重复误判为编译器缺陷。

### 关键设计点：边界从「类型」移到「操作」

* **不能**改 `types.is_unsafe_ty` 本身来落地本重分类 —— 该谓词在 irgen 侧还承担
  「指针/切片/原子类型的**槽型推断**」（`irgen_stmt_gen_p1.tie`、`irgen_expr.tie`、
  `irgen_closure.tie` 三处）。改它会让这些类型的变量生成错误槽型。做法是
  **类型分类照旧、只撤前端按类型拒绝的门禁**。
* 撤掉类型门禁后，`alloc` 返回的指针可以在安全函数里被**持有**，但**解引用**仍被
  内置清单拦住 —— 这正是设计要的「安全切片 vs 裸指针」两层结构。
* `unsafe fn` 仍是**有意义**的声明：函数体因此获得不安全上下文
  （`scheck_q3.tie` 的 `check_fn`：`sig_unsafe(sig) == 1 ⇒ g_unsafe_depth + 1`）。
  变的只是「签名里出现指针类型」不再是判定函数必须 unsafe 的依据。

## 第二轮落地记录（2026-10-01 下半场）：「产出指针值」类操作移出门禁

承接归类工作（`tie-main/docs/designs/domain-classification.md`）。归类时把每个门禁点逐条
按「危害面」归域，过程中发现判据可以**再收准一步**：光说「把边界从类型移到操作」还不够，
`mem` 域里的 11 项其实分两类——**触碰内存的**与**只算地址的**。

### 判据升级：从「是否危险」到「是否带安全前提」

**一个操作需要持证，当且仅当它要求书写者先满足某个安全前提。** 前提可以是
「指针有效」「内存已初始化」「未重复释放」「长度不越界」。

这条判据一举把 `mem` 域切干净：

| 类别 | 操作 | 前提 | 处置 |
| --- | --- | --- | --- |
| 触碰内存 | `deref` `deref_write` | 指针有效、在界内、所指已初始化 | 维持 unsafe |
| 触碰内存 | `alloc` `free` | 缓冲未初始化（读前须写）；未重复释放 | 维持 unsafe |
| 触碰内存 | `memcpy` `memset` | 目标区间有效（长度不越界） | 维持 unsafe |
| 触碰内存 | `volatile_load` `volatile_store` | 有效地址 + 语义不可优化 | 维持 unsafe（raw） |
| **只算地址** | `addr_of` `addr_of_field` | **无** | **移出门禁** |
| **只算地址** | `ptr_add` | **无**（普通 gep，无 inbounds） | **移出门禁** |
| **只算地址** | `ptr_to_int` `int_to_ptr` | **无** | **移出门禁** |

一句话边界：**产出指针值安全，用指针触碰内存须 unsafe**。

与 Rust 判法一致：`addr_of!` / `ptr as usize` / `without_provenance` / `wrapping_offset`
都是**安全函数**，只有 `read`/`write`/`alloc` 因带前提而 unsafe。判据与 Rust 的
「unsafe iff there are preconditions」是同一句话。
