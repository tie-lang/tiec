## 三、值得单独上报的两条

### 1. actor 字段初值被静默丢弃（`r_afield.tie`）

```tie
actor C { var n: i64 = 5;
    pub func get() -> i64 { return n } }
func main() -> i64 {
    var c = run C()
    println(to_string(c.get()))   // 实际输出 0，期望 5
}
```

编译**通过、无任何警告**，运行输出 `0`。规范 §10.8 明确要求「状态字段在声明处
给出初值，且初值必须是字面量」，实现未应用该初值。属**静默语义错误**——
不报错、值悄悄为零，比编译期拒绝更危险。ROAD p.8.3.1 标 `[ ]` 与实情相符，
但规范 §10.8 的示例初值恰好全是零值（`0` / `""` / `[]`），因此该缺陷在规范
示例中**不可观测**，建议规范补一个非零初值示例或在规范中标注此限制。

### 2. `reentrant` 关键字不存在（`r_reentrant.tie`）

规范 §10.7 用 `pub reentrant func route(id: i64) -> i64 { … }`；实测报
**E00484 @3:15 期望 'func'，实际是 标识符 'reentrant'`**。源码关键字表
（`frontend/lex_symtab.tie:36`，71 项）无 `reentrant`。ROAD.md 未见对应条目——
属**规范有、实现无、记录未提**的三方不一致。

## 四、方法论教训（已写入 method.md，供各分路遵守）

规范与 ROAD 里的示例是**散文式示意，未必逐字可编译**，判「未实现」前必须先排除
自己写法有误。本轮三次踩到：

1. `actor A { var n: i64 = 0\n pub func m() }` 报 E00000 —— 实为字段需分号
   （`parse_actor`：`pstmt_top_p3.tie:528`），非未实现。
2. `struct P { var x: i64 = 0\n var y: i64 = 0 }` 报 E00000 —— 同为字段分号/版式问题；
   改用规范原式（每字段独立行、`}` 独占一行）后通过。
3. 初次判 `actor` 未实现，实为样例写法有误。

即：**「实测失败」本身不足以判未实现，需先用规范自身或编译器源码里的等价写法复现**。

## 十、主代理工期自纠（重要：本轮我自己犯过两次误判，均已实测改正）

> 记录在此以警示：**「grep 不到」与「样例报错」都不足以判未实现**，必须换写法复核。
> 这两条误判若未纠正，会直接污染交付文档。

### 更正 1：`trim` 存在（原判「不存在」错误）

* 原判依据：`grep -rhoE '"trim"' frontend/*.tie backend/*.tie interp/*.tie` 无命中 → 判「不存在」。
* **实际存在**：`lead/verify/v_trim.tie` 实测 `s -> trim` 与 `trim(s)` 均通过，输出 `[hi]`。
* 真实机制：**p.9.13.2 语言前置注入**（`compiler/driver/prelude.tie`，82 行）——对 `logic` / `script` 角色，
  编译器在**正文首部**隐式拼入 `import "/std/prelude.tie" as lang` + `using lang;`，
  从而把 prelude 内的 pub 函数暴露为**裸名**（同名用户定义优先遮蔽）。prelude 实体在
  `tlib/std/prelude.tie`（库根，`$TIE_LIB_ROOT` 或 `~/.tiec-lib/tlib`）。
* 暴露的裸名共 16 个：`trim` `trim_start` `trim_end` `to_lower` `to_upper` `starts_with` `ends_with`
  `str_has` `seq_has` `seq_index` `map_has` `map_cat` `tbl_cat` `clamp_i` `pow_i` `pow_i_checked`。
* 我的 grep 落空原因：prelude 是**库文件**（在 tlib），不在编译器源码目录。

### 更正 2：映射能力已实现（原判「缺失」错误）

* 原判依据：样例用 `map_new()` / `age.has(...)` 均报错 → 判「映射能力缺失」。
* **实际已实现**，错在照抄了规范示例里的 API（`map_new` 根本不存在）。正确写法实测（`lead/verify/v_map.tie`）：
  * 创建：字面量 `var a: map<i64> = ["k": 1, "j": 2]` ✓
  * 判键：`map_has(a, "k")` → `true` / `false` ✓（**不是** `age.has(...)` 方法形态）
  * 合并：`a + b` 右侧优先 → `c["k"]` = 9 ✓（与规范 §3.10 一致）
  * 不可变更新：`a with { "k": 7 }` → 7 ✓（规范 §3.12 的映射形态，已实现）
  * 表拼接 `xs + ys` → len 3 ✓
* 故 §3.9/§3.10/§3.12 的映射相关条目应记 **已实现**；真正的问题是
  **规范示例引用了不存在的 API**（见下「规范缺口」）。

### 据此修正：内建与 prelude 函数的管道能力差异（精确表述）

| 类别 | 能作管道目标？ | 例 |
| --- | --- | --- |
| prelude 暴露的普通函数 | **能** | `s -> trim` ✓（`v_trim.tie`） |
| 用户自定义函数 | **能** | `v -> f` ✓ |
| 编译器内建原语 | **不能** | `v -> to_string` / `v -> len` ✗ `E00488 未声明的变量 'to_string'` |

即：管道目标必须是**可见的标识符**（表达式位置的一等函数名），内建原语只在内建调用位置识别，
不作一等标识符。原表述「内建函数不能作管道目标」成立，但不可推广为「函数不能作管道目标」。

### 因此新增的规范缺口（实现有、规范未写）

* 规范 §3.11 的管道示例直接用 `trim`，但规范**通篇未提「隐式前置」这一机制**（没有一节讲
  logic/script 免 import 获得裸名函数）。读者无从知道 `trim` / `to_lower` / `map_has` 从哪来、
  边界是什么（只 `logic`/`script` 注入、`class` 不注入、prelude 缺失则静默降级）。
* 规范 §2.5 用 `age.has(...)`、ch16 速查表 §16.6 用 `map_new()`，二者在实现里都**不存在**；
  实现提供的是 `map_has(m, k)` 与映射字面量。**规范示例与实现的正误是反的**。
